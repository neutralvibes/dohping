| 66 | REFLOWING-terminal re-anchor via cursor query (DSR/CPR) — the root fix for the creep/residue reports. On a reflowing terminal (Windows Terminal, Terminal.app, iTerm2 — they re-wrap existing lines on resize; xterm/gnome-terminal do not), the relative walk-back bookkeeping (#65) goes stale: a shrink re-wraps the live line so the next write starts at its tail ("does not clear the rest on wrap"), and a grow-back collapses the wrap so the walk-back overshoots (creep UP — also the true cause of the #64 window creep, which was misattributed to height-scroll). Fix: when the terminal WIDTH changes since the last write, the display queries the terminal's cursor position (`\x1b[6n` → `\x1b[<row>;<col>R`, via an app-owned `reanchor` callback — the app owns stdin; the key reader parses CSI sequences and delivers CPR responses on a dedicated channel, 150ms timeout).
