| 67 | CORRECTION (supersedes #66): the DSR/CPR re-anchor is REPLACED by freeze-and-restart. The CPR answer on Windows Terminal/WSL comes from ConPTY, whose internal reflow differs from the rendered view — Microsoft documents it returning "wildly incorrect cursor positions" on resize (microsoft/terminal#18725; the repro there is PowerShell in VS Code, but the failing component is the same: ConPTY emulates the terminal and answers DSR in both setups). The #66 anchor was therefore garbage on the user's platform, and round 8's CPR was "still not working". Fix: the displays never reclaim a reflowed rendering. On width change they FREEZE in-place writes (300ms settle window — the clock RESTARTS on every further width change, so a resize drag extends the freeze; verified per user check); once the width is stable, they emit `\r\n` to a fresh row below the frozen (re-wrapped) rendering and continue there — the old rendering stays in scrollback as history.
